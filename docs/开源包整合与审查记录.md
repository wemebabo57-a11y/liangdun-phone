## 二、剔除清单（逐项）

| 盗版警告页 | `PiracyWarningActivity.java` | **整文件删除**（内含另一份内联指纹重建逻辑） |

| 资源加密密钥（种子 / 盐） | `app/src/main/cpp/crypto_core.h` | 16 字节密文数组 → **占位值 0x00**（XOR 掩码逻辑保留，便于接回自有密钥） |
| 资源混淆 + 加密构建管线 | `app/build.gradle` 尾部 | `obfuscateAssets()` / `encryptAssets` / `assets.srcDirs` / `preBuild.dependsOn` 全部删除，同时**不再需要 Node.js** |

**连带后果（有意为之）**：前端资源不再是"签名绑定的密文"，而是**明文**
`app/src/main/assets/index.html`；运行期由 `MainActivity.decryptAndServe()`
直接读明文提供；`MainActivity` 里原本"预校验 index.html 可解密、失败就退出"的逻辑，
改为"确认资源存在且非空"。因此**任何人重新签名都能正常运行**。

### 2.2 自动拦截病毒库（按作者要求：不含）

| 删除/改动 | 位置 | 说明 |

| 病毒库服务器域名 + 5 个列表路径 | `StrX.java` 中 `VDB_*` 字节常量 | 整组删除 |

检测/卸载流程的代码都还在，接上数据源即可复用。

## 四、想恢复这些能力时怎么做

1. **病毒库**：把 `VirusDb` 里的 `SERVER_HOST_D` 与 5 个 `URL_*` 换成你自己的地址，
   把 `refreshAsync/refreshNow` 恢复为调用 `refreshNowLegacy()`。
2. **资源加密 + 签名绑定（防盗版）**：自己生成 keystore → 在 `app/build.gradle` 里加回
   `signingConfigs` 与构建期加密任务（参考 `AssetsEncryptor` 与 `getCertFingerprint()` 的旧逻辑）
   → 把真实种子/盐填回 `app/src/main/cpp/crypto_core.h` → 运行期恢复
   `MainActivity.decryptAndServe()` 的解密分支（`AssetsEncryptor` 类仍然保留）。
3. **签名校验**：参考被删除的 `SignatureVerifier` / `PiracyWarningActivity`，
   用**你自己的**证书指纹重写一份（不要再把口令写进注释里）。

> ⚠️ 顺带提醒：原工程源码注释里直接写了 keystore 口令与别名，
> 这类信息**不要**再出现在任何会公开的地方；keystore 本体也务必放在仓库之外。
