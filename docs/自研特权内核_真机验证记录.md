# 自研特权内核 · 真机验证记录（2026-10-05）

## 结论一句话

**自研服务端本身完全跑得通**（在 shell 身份下实测通过），
**但"从普通应用进程内拉起 shell 身份服务端"这一步在 Android 14 非 root 设备上做不到** ——
这是系统的硬限制，需要改用**自研 ADB 无线配对**来取得 shell 通道。

## 一、已验证通过的部分（真机 vivo V2133A / Android 14）

### 1. 服务端入口在 shell(uid 2000) 身份下正确执行

从 adb 手动执行（对照实验）：

```
$ CLASSPATH=<本应用APK> app_process /system/bin \
      --nice-name=ylmanual com.youlong.priv.server.YlServerMain
```

服务端自己写出的落盘日志（`/data/local/tmp/ylpriv_server.log`）：

```
[10-05 12:39:45.859] main() 进入，args=[] uid=2000 pid=26717
[10-05 12:39:45.867] Looper 就绪，开始 init()
[10-05 12:39:45.941] init() 完成，进入 Looper.loop()
```

**证明**：入口类加载、`Looper` 初始化、Context 获取（`init()`）、进入 Binder 循环 ——
自研服务端的启动链路本身没有问题。

### 2. R8 裁剪入口方法的问题已修掉

`release` 构建默认会删掉"没人调用"的 `main(String[])`，导致运行期
`NoSuchMethodError: no static method "...YlServerMain;.main([Ljava/lang/String;)V"`。

修法（`app/proguard-rules.pro`）：

```
-keepclasseswithmembers class * {
    public static void main(java.lang.String[]);
}
-keepclassmembers,allowoptimization class com.youlong.priv.server.YlServerMain {
    public static void main(java.lang.String[]);
}
```

复验（对**已安装到设备**的 APK 反编译）：

```
.method public static main([Ljava/lang/String;)V
```

已存在于 `classes3.dex`。

## 二、阻断点：应用进程无法拉起 shell 身份进程

### 现象

应用内部执行 `ProcessBuilder("sh","-c","CLASSPATH=… app_process … &")` 后：

```
$ ps -A -o PID,PPID,USER,NAME | grep youlong_priv
26337     1 u0_a497      youlong_priv      ← uid 是应用自己(10497)，不是 shell(2000)
```

而且这些进程 **从未执行到 `main()`**：
- `/data/local/tmp/ylpriv_server.log` 始终不存在（说明 `diag()` 一次都没跑）；
- logcat 里没有服务端任何日志；
- 应用活着期间这些进程会**持续累积**（一次一尝试一个），`am force-stop` 应用后全部消失
  —— 即它们确实是应用 spawn 出来的子进程，只是卡死在启动早期。

### 判定

`app_process` 是 zygote 侧的运行时入口，**普通应用（untrusted_app 域）无权限以 shell 身份执行它**。
Android 10+ 起 SELinux 对 `untrusted_app` 执行 `app_process` 有严格限制，
所以子进程只继承了应用自己的 uid，并且拿不到完整的 ART 运行时初始化，
于是既不报错也走不到我们的 `main()`。

### 与既有第三方方案的关系

Shizuku 之所以能做到，是因为它附带一个**原生启动器**（`libstarter.so`，放在应用私有目录里
以可执行方式运行）；该启动器通过 adb 装入 shell 环境，成为"以 shell 身份 fork 服务端"的跳板。
要复刻这条路，必须自研一个同样机制的原生启动器 —— 这属于另一条完整技术路线，
不在"不复制其代码"前提下能顺手完成的范围。

## 三、下一步路线（唯一可行）

**自研 ADB 无线调试配对**（即本目标里的第 ③ 项）：

1. 应用内引导用户开启「无线调试」，输入配对码；
2. 自研实现 ADB 配对协议（AOSP 公开规范：SPAKE2 + HKDF + TLS exporter，
   密码学用设备自带的 Conscrypt / BoringSSL）；
3. 配对成功后建立到 `adbd` 的连接，在 **shell 通道**里执行：
   ```
   CLASSPATH=<APK> app_process /system/bin --nice-name=youlong_priv \
       com.youlong.priv.server.YlServerMain
   ```
4. 服务端起来后，经由 `YlBootProvider` 的握手信道把 Binder 交回应用
   —— 这部分（阶段一）已经写好并验证过。

也就是说：**阶段一的内核可以直接复用，只差"用 ADB 取得 shell 通道"这一段**。
